# Custom Fish Asset Workflow

Use this guide for any fish or fish-like aquatic creature that needs
vanilla-consistent Animal Crossing GameCube assets: the inventory/encyclopedia
icon and the catch/held/release model-preview asset.

This is the required/default workflow for custom fish art in this repo. When a
prompt asks to make or replace fish assets, follow this file unless the user
explicitly asks for a different process.

The core rule is:

**Vanilla base first. Species markings second. Preview before implementation.**

Do not begin by wiring a finished asset. First make preview candidates beside
the vanilla fish grid, choose one, get approval, then implement only the approved
candidate.

The process was proven on fish #41, neon tetra. The most important lesson is:
do not start by wiring a finished asset. First make preview candidates beside
the vanilla fish grid, choose one, then implement only the approved candidate.

## Scope

Only work on these asset classes unless explicitly asked otherwise:

- Inventory/encyclopedia icon in `src/data/model/inv_mwin3.c` and
  `src/data/model/inv_mwin_<id><name>_tex.c_inc`.
- Catch/held/release model-preview asset generated by `fish/gen_fish_model.py`
  into `src/data/model/act_f<id>_<spec>.c`.
- Model display-list wiring in `src/actor/ac_gyoei_model.c_inc`.
- Existing compile include for the generated model in `src/f_furniture.c`, only
  if the build requires it.

Do not touch tank, furniture, spawn, price, encyclopedia slot, museum, or catch
text logic during this workflow.

Do not edit or add anything related to:

- `ac_sum_*.c`
- `ac_mod_fish_tank.c`
- furniture profiles
- placed fish furniture behavior
- room placement
- fish tank behavior
- spawn tables
- sell price
- encyclopedia slot
- museum behavior
- catch text
- tank rendering

If the repo requires generated `act_f<id>_<spec>.c` model files to be included
from `src/f_furniture.c` for compilation, add only the include line needed by
the existing local include style. Do not touch furniture actor logic, furniture
profiles, room placement, tank rendering, or fish tank behavior.

## Recommended Prompt Shape

```text
For <fish name> / fish #<id>, create vanilla Animal Crossing GameCube fish
asset previews first. Do not implement or wire anything yet.

Create 3 candidate 32x32 CI4 inventory-icon designs beside the vanilla fish
icon grid. Create a 4th candidate only if there is another clearly useful
vanilla structural base.

Use existing vanilla fish icons as structural bases. Preserve the base icon's
silhouette, eye size, tail size, fin placement, pixel density, and shading
style. Only adapt colors and markings enough to suggest <fish name>.

After I approve one candidate, implement that exact icon and create the matching
catch/held/release model-preview asset. Keep scope limited to fish #<id>'s
icon and generated model.
```

## Phase 1: Choose Vanilla Bases

Pick nearby vanilla fish icons by shape, not by species accuracy.

Examples:

- Tiny ornamental fish: `gupi`, `kingyo`, `demekin`.
- Simple tiny/small fish: `medaka`, `funa`, `tanago`, `wakasagi`.
- Chunkier river fish: `bass`, `blue_gill`, `donko`.
- Long fish: `unagi`, `ayu`, `sake`.
- Sea fish: `suzuki`, `tai`, `ishidai`.
- Special aquatic cases: `kurage`, `zarigani`, `kaeru`.

For non-fish aquatic creatures, choose structural bases from the closest vanilla
special cases such as `kurage`, `zarigani`, or `kaeru`, and do not force a
standard fish silhouette.

Choose references based on:

- Body silhouette.
- Eye placement.
- Fin/tail style.
- Shading/ramp style.
- Animation/model proportions.

Briefly explain which references were chosen and why.

## Phase 2: Translate Species Anatomy Into Vanilla Style

Use real species anatomy only as inspiration.

Do not copy real anatomy literally if it conflicts with vanilla style.

For the target species, identify only the few traits needed for recognition:

- body shape
- head shape
- tail shape
- fin type
- main body color
- belly color
- one or two markings
- any unusual silhouette feature

Then simplify those traits into vanilla rules:

- chunky readable silhouette
- compact side profile unless the species truly requires a long body
- small vanilla-style eye
- soft 1–3 pixel ramps
- limited markings
- low-contrast fins
- selective shadow pixels
- no hard black outline
- no photoreal gradients
- no screenshot tracing
- no overly crisp modern pixel art
- no rectangular background artifacts

Prioritize:

```text
vanilla consistency > silhouette readability > species accuracy
```

The asset should read as:

```text
A vanilla Animal Crossing GameCube fish inspired by this species.
```

Not:

```text
A realistic species sprite forced into Animal Crossing.
```

## Phase 3: Make Preview Candidates Only

Create previews under `build/preview_<fish>/` or another ignored build folder.

Do not edit tracked source files in this phase.

Create 3 candidates by default. Create a 4th only if there is another clearly
useful vanilla structural base.

Each candidate should include:

- A 32x32 PNG preview at 1x.
- A 4x or 8x enlarged PNG preview.
- A swizzled CI4 texture include with exactly 512 byte literals.
- A palette include if useful.
- A sheet showing candidates beside `fish/Fish_Encyclopedia.png`.

Preview candidates should preserve the vanilla base icon's:

- Body silhouette.
- Eye size and placement.
- Tail and fin placement.
- Pixel density.
- Shading/ramp style.
- Round blue item-disc background.

Only change the fish colors and markings enough to suggest the new fish.

The candidates should look like conservative vanilla variants, not newly
invented modern sprites.

## Phase 4: Icon Art Rules

All inventory/encyclopedia icons must follow these rules:

- 32x32 CI4 texture.
- Vanilla blue item-disc background preserved.
- Chunky readable fish silhouette.
- Small vanilla-size eye.
- Soft 1–3 pixel ramps.
- Compact highlights.
- Simplified anatomy.
- Low-detail fins.
- Selective dark shadow pixels instead of hard outlines.
- No hard black outline.
- No photoreal gradients.
- No screenshot tracing.
- No overly crisp modern pixel art.
- No rectangular background artifacts.

Avoid:

- long thin torpedo bodies unless the species truly requires it
- rectangular bodies
- clean horizontal color blocks
- crisp single-pixel laser stripes
- huge pasted-on accent markings
- disconnected tails
- oversized eyes
- modern sprite sharpness
- excessive anatomical detail

A good vanilla adaptation usually uses:

- one main upper-body color
- one belly color
- one soft highlight or stripe
- one small accent marking if needed
- selective dark pixels instead of a full outline

The installed icon should be a real custom asset. A conservative vanilla variant
is good, but avoid a pure palette-only reskin unless the user explicitly approves
that.

## Phase 5: Evaluate Candidates

Evaluate candidates against the vanilla grid, not against a photo alone.

Use this checklist:

- Does the silhouette feel like an existing vanilla fish icon?
- Is the eye vanilla-sized and placed like the base icon?
- Are tail and fins integrated, not pasted on?
- Are shadows selective instead of a hard outline?
- Are color ramps chunky and soft, not modern or crisp?
- Does the signature marking read at 32x32 without dominating?
- Does the fish avoid becoming rectangular, pointed, realistic, or too clean?
- Does it fit naturally beside the surrounding vanilla fish icons?

Reject a candidate if:

- it looks too realistic
- it looks too modern
- it looks too clean or crisp
- it has a hard black outline
- the body is rectangular
- the body is too flat
- the tail looks pasted on
- the eye is oversized or misplaced
- the markings dominate the silhouette
- the asset does not fit beside the vanilla fish grid

If none fit, make more candidates from different vanilla bases.

Pick the strongest candidate and explain why.

## Phase 6: Approve One Candidate

Do not implement until one preview is explicitly approved.

When approved, preserve it as closely as possible. The implementation step is
not a redesign pass. If changes are necessary, keep them to palette or tiny
pixel-level corrections required by the repo's CI4 format.

After choosing the strongest candidate, make one final small preview revision.

Do not redesign from scratch.

Final revision rules:

- Keep the selected candidate’s vanilla base silhouette.
- Make only small pixel-level refinements.
- Reduce harsh outlines.
- Soften overly crisp markings.
- Keep accent markings subtle.
- Keep the vanilla-style eye.
- Keep the body chunky and readable.
- Keep the tail integrated with the body.
- Preserve the vanilla blue item-disc background.

Show the final revised candidate beside the vanilla fish grid.

Wait for approval before implementation.

## Phase 7: Install The Icon

After approval, implement the approved icon.

Do not redesign the icon. Preserve the approved preview as closely as possible
within the repo’s CI4 texture/palette constraints.

For fish #41 neon tetra, the installed symbols were:

- `inv_mwin_41tetra_pal`
- `inv_mwin_41tetra_tex`
- `src/data/model/inv_mwin_41tetra_tex.c_inc`

For future fish, follow the repo’s existing local naming pattern for the target
fish.

General icon rules:

- Keep palette index `0` transparent.
- Keep palette entry `1` as `0xB19F`.
- If using a 32-entry palette, keep entry `17` as `0xA66D`.
- Put the approved 32x32 swizzled CI4 texture in the fish's texture include.
- Verify the texture include has exactly 512 `0xNN` byte literals.
- Verify `src/game/m_submenu_ovl.c` `fish_tex_table[]` points to the fish's
  custom `{ pal, tex }` pair.

For a 16-color approved preview palette, duplicate entries 0–15 into entries
16–31, except preserve entry 17 as `0xA66D`.

The installed icon should still visually match the approved preview after
decoding.

## Phase 8: Generate The Model Preview

Update the fish spec in `fish/gen_fish_model.py` using the approved icon as the
art direction.

The model preview should follow the approved icon’s visual language. Do not use
model generation as an excuse to redesign the fish toward realism.

Tune shape first:

- `length`
- `height`
- `tail_x`
- `belly_scale`
- any local shape flags used by the generator

Then tune colors:

- `outline`
- `back`
- `belly`
- `stripe`
- `stripe2`
- `rear`
- `rear2`
- `eye`
- `eye_white`
- `fin`

Use the generator:

```bash
py fish/gen_fish_model.py <spec-name>
```

The generated model should keep the vanilla structure:

- 16-color RGB5A3 palette, index 0 transparent.
- 32x32 CI4 texture.
- Low-poly side-profile mesh.
- Three frames: `a`, `b`, `c`.
- Tail/rear-body motion across frames.

Do not hand-edit `src/data/model/act_f<id>_<spec>.c` unless the generator cannot
express the needed asset.

Prefer improving the generator/spec and regenerating.

## Phase 9: Wire The Model

In `src/actor/ac_gyoei_model.c_inc`:

- Add externs for `act_f<id>_<spec>_aT_model`, `bT_model`, and `cT_model`.
- Add a static `aGYO_<spec>_dl`.
- Point the fish's `aGYO_displayList[]` entry to that display-list struct.

Example shape:

```c
extern Gfx act_f<id>_<spec>_aT_model[];
extern Gfx act_f<id>_<spec>_bT_model[];
extern Gfx act_f<id>_<spec>_cT_model[];

static aGYO_DL_c aGYO_<spec>_dl = {
    act_f<id>_<spec>_aT_model,
    act_f<id>_<spec>_bT_model,
    act_f<id>_<spec>_cT_model,
};
```

If this repo still compiles generated `act_f` files by including them from
`src/f_furniture.c`, add only the include line following the existing local
include style for nearby `act_f` files.

Current repo pattern:

```c
#include "../src/data/model/act_f<id>_<spec>.c"
```

Do not touch furniture profiles, room placement, tank rendering, or
`ac_sum_*.c`.

## Phase 10: Release Animation

Use the existing release animation table in `src/actor/ac_gyo_release.c`.

- Pattern `1`: quick small-fish wiggle.
- Pattern `2`: slower large/long fish movement.

Tiny ornamental fish should usually use pattern `1`.

Large, heavy, or long-bodied fish should usually use pattern `2`.

Do not change release behavior beyond choosing the appropriate existing pattern
for the target fish.

## Phase 11: Verification

Before finishing, check:

1. The installed icon decodes visually and still matches the approved preview.
2. The icon texture include contains exactly 512 bytes.
3. Palette entry `1` is `0xB19F`.
4. Palette entry `17` is `0xA66D` if using 32 entries.
5. `fish_tex_table[]` points to the custom icon.
6. The generated `act_f<id>_<spec>.c` exists.
7. The generated model has `a`, `b`, and `c` frames.
8. The generated model has tail/rear-body motion across frames.
9. `aGYO_displayList[]` points to the custom model display-list struct.
10. The release pattern is appropriate.
11. Run:

```bash
py -m ninja
```

For this modded repo, compile/link success followed by a final `foresta.rel`
checksum mismatch may be expected after intentional asset changes. Report the
checksum result clearly.

## Case Study: Neon Tetra / Fish #41

Neon tetra only converged after switching to preview candidates:

1. Preview candidates were generated beside the vanilla fish grid.
2. The approved final icon was candidate L, based on the `wakasagi` icon.
3. Candidate L kept the vanilla pale blue/silver small-fish proportions.
4. Its neon tetra traits were color placement only: dark back, cyan side flash,
   pale belly, red lower rear/tail.
5. The implemented texture was copied exactly from the approved preview include.
6. The model spec was then adjusted to match the approved icon, not a realistic
   photo silhouette.

This is the preferred pattern for future fish:

**vanilla base first, species markings second.**

Do not assume future fish should use `wakasagi`. That was specific to neon tetra
because its approved vanilla fit was a pale silver/blue small-fish structure.

For each new fish, choose the vanilla structural base that best matches that
fish’s simplified silhouette, scale, and icon language.
